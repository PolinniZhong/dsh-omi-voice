# Changelog

本文件记录 Omi 面向使用者的版本变化。

## [Unreleased]

开发中的使用者可见变化先记录在这里。发布时将内容移入带日期的版本章节，并重新保留空的 `Unreleased`。

## [0.1.3] - 2026-08-05

本版本完善桌面端的长期使用体验与播放状态反馈。仍为 macOS 仅源码 Developer Preview，不提供未经正式签名和公证的 App 二进制。

### Added

- 设置页新增“应用偏好 > 开机启动”开关，直接注册或移除 macOS 登录项；系统需要确认时引导用户前往“登录项”设置。
- 增加播放倍率偏好：首次启动为 `1.2×`，有效范围内的上次倍率会在下次打开 Omi 时恢复。

### Changed

- 应用名称统一为“Omi 朗读小助手”，菜单栏退出项统一为“退出 Omi”。
- 朗读中以四条 2 px 细线的动态波形表示播放；最高线高度下调，图标与状态文字按同一基线对齐。
- 暂停状态使用中性扬声器图标，与朗读中的波形反馈区分。

### Validation

- 完成开机启动的启用与关闭验证、倍率跨重启恢复验证，以及 V0.1.3 构建与签名校验。

## [0.1.2] - 2026-08-03

本版本增加进程内纯文本预览，并在朗读前过滤表格、拦截无有效文字和安全分段长文本。仍为 macOS 仅源码 Developer Preview，不提供未经正式签名和公证的 App 二进制。

### Added

- 在 300 pt Omi 控制器的设置模式中增加“朗读配置 / 文本预览”双 Tab；两个页面互斥显示，不新增第二个窗口或菜单栏入口。
- 文本预览支持手动聚焦后使用系统 `⌘V` 粘贴、滚动、选择、系统 `⌘C` 复制与内嵌“清空”。内容只保留在当前 Omi 进程内，退出后清空。
- 显式粘贴时可从剪贴板 HTML 中恢复数字列表与圆点列表为普通纯文本标记；列表换行使用悬挂缩进，便于对齐阅读。
- 增加 `preview-paste-test` 和 `reading-text-test` 两项离线验证。

### Changed

- 朗读请求在本地过滤高置信度 Markdown、HTML 和制表符表格，只把剩余可朗读文本送入缓存与豆包 TTS。
- 长文本在本地按句子或自然停顿边界切分，每个请求片段最多 900 UTF-8 字节，再按原顺序连续播放；尚未实现后续分段预取。
- 朗读预处理日志只记录原始字符数、发送字符数、表格块数和分段数，不记录文本内容。

### Fixed

- 修复原生文本预览只能键盘输入、系统复制粘贴不生效的问题。
- 修复从网页复制的数字列表和圆点列表丢失标记，以及列表换行从最左侧开始导致阅读不齐的问题。
- 修复表格虽然不产生音频，却仍被整体发送并计入豆包用量的问题；纯表格不再发起 TTS 请求。
- 空白、纯标点、纯 Markdown 符号和纯 Emoji 在本地直接拦截，不读取 Keychain 或请求豆包。

### Privacy

- 文本预览与朗读的 `currentText`、TTS、PCM 队列和音频缓存完全隔离；预览内容不会发送给豆包，也不会写入文件、历史或同步服务。
- 剪贴板可选 HTML 只在本地识别列表或表格结构；原始 HTML 不会发送给豆包或写入日志。

## [0.1.1] - 2026-07-30

本版本聚焦播放状态准确性、暂停续播、重复音频成本控制和紧凑播放器交互。仍为 macOS 仅源码 Developer Preview，不提供未经正式签名和公证的 App 二进制。

### Changed

- 优化 README 的快速概览、跨桌面 AI 兼容性说明、使用场景、安装引导与常见问题，以提高 Omi 在 AI 回复朗读相关检索中的可发现性。
- 朗读状态拆分为“正在准备朗读”“朗读中”“已暂停朗读”“朗读完成”“已停止朗读”。
- 悬浮面板在朗读中提供暂停/续播，保留当前 PCM 队列和播放位置；菜单栏“停止朗读”继续执行取消请求并清空音频的硬停止。
- 悬浮控制器固定为 300 pt，使用单位置朗读操作和原生线性齿轮配置入口；用户隐藏面板后，快捷键启动朗读但不再自动唤回面板。
- 完整朗读成功后在内存中缓存上一条 PCM；相同文本、模型、Resource ID、音色、语速和采样率再次朗读时直接本地重播。重复触发仍在进行的相同朗读时继续当前会话，不创建第二次豆包请求。
- 暂停后点击继续从原播放位置恢复，不从头播放，也不重新请求豆包。

### Fixed

- 只有最后一个 PCM Buffer 真正播放完毕后才显示“朗读完成”，不再把豆包网络流结束误判为本机播放结束。
- 活跃朗读遇到空或非文本剪贴板时保持当前状态和声音；零有效 PCM 进入明确失败状态。
- 播放开始后网络流失败会立即停止并清空剩余 PCM；连续请求通过会话代次隔离旧回调，避免状态覆盖和音频串流。

## [0.1.0] - 2026-07-29

首个 macOS 源码构建版 Developer Preview。该版本只发布源码，不提供未经签名和公证的 App 二进制。

### Added

- 使用 `⌘C → ⌥⇧Q` 朗读系统剪贴板中的纯文本。
- 支持 Codex、Kimi Work、豆包及其他能够复制纯文本的 macOS 桌面应用。
- macOS 菜单栏入口与独立悬浮播放器。
- `1.0×–2.0×`、步长 `0.1×` 的离散语速选择，默认 `1.2×`。
- 豆包 TTS 1.0、V3 HTTP 单向流式播放。
- Omi 设置页，可配置模型、API Key、Resource ID 和音色 ID。
- 独立 Finder / Spotlight 启动器，无需每次通过终端启动。
- 协议、请求载荷、设置和日志脱敏的离线验证命令。

### Security and privacy

- 使用者必须提供自己的豆包 API Key（BYOK）。
- API Key 只保存到 macOS Keychain，保存后不回显。
- 只在用户主动触发时读取当前剪贴板纯文本。
- 不保存朗读文本、音频或朗读历史。
- 诊断日志不记录 API Key、请求 Header、朗读文本或服务端原始响应体。

### Known limitations

- 仅支持 Apple Silicon Mac 和 macOS 13+。
- 需要版本匹配的 Xcode Command Line Tools 或完整 Xcode 从源码构建。
- 尚未实现长文本自动分段和预取。
- 尚未完成 Apple Developer 正式签名、公证、安装器和自动更新。
- 当前 Keychain 访问策略面向未正式签名的本机开发包；正式签名版本需要迁移到 Data Protection Keychain 与正式 Access Group。
